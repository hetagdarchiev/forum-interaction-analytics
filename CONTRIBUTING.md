# 🛠 Регламент разработки

Этот регламент помогает поддерживать чистоту кода и стабильность проекта. 

> 🚫 **Важно: прямые пуши в `main` строго запрещены.** Все изменения попадают в основную ветку только через Pull Request и проверку.

## 🔄 Рабочий цикл

1. **Синхронизация** *(обязательно перед началом работы)*
   Обновите локальную версию репозитория, чтобы работать с актуальным кодом и избежать конфликтов:
   ```bash
   git pull
   ```

2. **Создание ветки**
   Для каждой новой задачи всегда создается отдельная ветка с правильным префиксом:
   ```bash
   git checkout -b тип/название-задачи
   ```

3. **Отправка изменений**
   После завершения работы отправьте вашу ветку на сервер:
   ```bash
   git push origin тип/название-задачи
   ```

4. **Создание Pull Request (PR)**
   Откройте PR на GitHub и обязательно дождитесь проверки (Code Review) от другого участника команды.

5. **Слияние (Merge)**
   Выбор стратегии зависит от размера PR:
   * **1 коммит в PR:** используйте **Rebase and merge**. Это сохранит историю коммитов плоской и линейной.
   * **Серия коммитов:** используйте **Create a merge commit (Merge)**. Это сгруппирует масштабную фичу в единый смысловой блок в истории.

---

## 📝 Методология именования (Conventional Commits)

Название ветки и коммита должно начинаться с префикса. Это позволяет понять суть изменений без открытия самого кода.

| Тип | Описание |
| :--- | :--- |
| `feat/` | **Новая функциональность** (Feature) |
| `fix/` | **Исправление багов** и ошибок |
| `refactor/` | **Рефакторинг**: переписывание структуры кода без изменения его поведения |
| `chore/` | **Рутина**: настройка конфигов, Docker, CI/CD, обновление зависимостей |

---

## 💡 Примеры именования

**Новые функции (`feat/`)**
* `feat/login-form`
* `feat/cart-calculation`
* `feat/notifications-socket`

**Исправление ошибок (`fix/`)**
* `fix/header-overflow`
* `fix/payment-validation`
* `fix/crash-on-empty-list`

**Оптимизация кода (`refactor/`)**
* `refactor/api-client`
* `refactor/useAuth-composable`
* `refactor/store-structure`

**Технические задачи (`chore/`)**
* `chore/eslint-config`
* `chore/update-deps`
* `chore/ci-cache`
